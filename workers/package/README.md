# Offline worker package contract

English · [简体中文](README.zh-CN.md)

This independent Rust library defines the signed Windows worker package format for controller assembly and native verification. The format uses a canonical UTF-8 JSON manifest with sorted file keys and one final LF, plus an Ed25519 detached signature. Verification requires an independently pinned public key; `manifest.pub` delivered beside a package cannot establish trust in that package. The low-level signing interface returns PKCS#8 bytes to the controller caller and never serializes a private key into manifests or signatures.

`load_controller_signer` creates one stable controller identity with exclusive atomic publication. On Windows, private bytes use current-user DPAPI and protected user/SYSTEM-only directory/file ACLs. On Unix, the directory/file must belong to the caller with modes 0700/0600. Existing unsafe permissions, links and damaged key material fail without replacement. Temporary DPAPI output and decrypted file buffers are cleared after use; the signing object is neither serializable nor printable. This protects keys at rest from other ordinary users, without protecting a compromised controller account or administrator. Key backup/rotation and desktop enrollment remain separate work; never copy this directory to VM payloads or migration/export bundles.

`seal_package` checks compatibility and the complete payload tree before signing, writes metadata without overwriting existing files, then verifies the resulting signed tree. Its controller utility is `wukong-package.exe`; the worker runtime does not expose signing RPCs and the assembler excludes this controller executable. The [native component guide](../windows/README.md) documents controller assembly. A signed tool payload alone does not provide native service installation or production isolation.

Public VM enrollment records bind a positive generation, installation/environment IDs, controller signing public key, exact payload manifest hash, SSH management peer/port and a canonical Ed25519 SSH public key. They contain no private keys. Enrollment signatures use the distinct `Wukong/Windows-worker-enrollment/v1\0` domain and canonical JSON, with a 16 KiB limit; incoming records cannot replace existing installation trust. Initial trust requires the VM owner and trusted controller delivery. `VerifiedEnrollment` requires an independently supplied key and binds a verified payload before publication; SSH key text cannot include authorized-key options, commands or newlines. Re-enrollment must preserve authority/installation/environment identity and exceed the protected highest accepted generation, including failed activations; identical requests reconcile their receipts instead of reactivating old keys. The controller-only `enroll` utility verifies actual package files and writes fresh `enrollment.json`/`enrollment.sig` output. These records are the native installer input contract; installation provisions the dedicated account/service, and the desktop imports the public connection record. Acceptance is source-bound in the Windows component guide.

The manifest binds package/source versions, runtime protocol, minimum controller version, the toolchain lock file/hash, native/Python/debugger/SSH entry points, every file's SHA256/size/type and license notices. Manifest schema 2 requires the WinDbg MCP and self-test entry points and rejects schema 1 without migration. Python, Debugging Tools, OpenSSH and WinDbg MCP require their original payloads and licenses. The explicit `workers/windows/python-components.json` inventory selects analysis sources and standard-library-only Windows helpers; Linux worker modules and dependencies are excluded. Component declarations and valid signatures do not prove vendor dependency closure or functioning tools; the assembler must check pinned official payload inventories, and actual offline VM installation/self-tests remain required.

Limits are 4 MiB per manifest, 20,000 files, 2 GiB per file and 8 GiB of payloads. Package member paths use a portable ASCII subset; installation roots can contain Unicode. Reject traversal, alternate data streams, Windows device names, trailing-dot/space aliases, case collisions and file/directory collisions. Complete-tree verification also rejects missing/extra/changed files, symlinks and Windows reparse points, including linked ancestors. Callers must keep the root private from untrusted writers throughout verification/copying; native extraction still needs protected ACLs and safe creation. These checks do not provide concurrent-write isolation by themselves.

Run the portable contract checks:

```powershell
cargo fmt --manifest-path workers/package/Cargo.toml -- --check
cargo clippy --locked --manifest-path workers/package/Cargo.toml --all-targets --target-dir target/worker-package-checks -- -D warnings
cargo test --locked --manifest-path workers/package/Cargo.toml --all-targets --target-dir target/worker-package-checks
```

Windows CI builds the static native verifier and controller package utility, then explicitly runs the ignored CLI integration tests with `WUKONG_WORKER_CLI` and `WUKONG_PACKAGE_CLI` pointing to those self-built binaries. They seal/verify inert fixtures, check persistent protected key storage, refuse in-payload key directories and reject a different pinned key or tampered bytes; they do not execute fixture payloads. The native verification command is `wukong-worker verify-package DIRECTORY PINNED_PUBLIC_KEY_HEX CONTROLLER_VERSION`. Its success covers signature, compatibility and file integrity, not installation or production isolation.
