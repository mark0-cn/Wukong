# Format-string primitive analysis

Use when attacker-controlled bytes reach the format argument of a printf-family
function. `printf("%s", input)` is not that condition. Identify the exact call,
format source, destination stream, length handling and filtering first.

## Separate argument access, read and write primitives

Use bounded probes and a recognizable marker to locate controlled argument words.
Record ABI, pointer width, endianness, alignment and argument indices. An index
that prints the marker is evidence of argument access, not automatically an index
containing a valid writable pointer. Revalidate after changing payload layout.

A leaked pointer requires an identified referent and mapping before deriving a
base. `%s` dereferences a pointer and can fault or truncate; bound precision and
observe the bytes actually returned. Preserve embedded NUL/newline behavior and
whether the input function terminates, drops or transforms bytes.

## Prove a write destination before constructing writes

Establish that the chosen argument resolves to the intended address, the mapping
is writable, the width is valid and the destination remains live until use.
Test a small observable state change before claiming an arbitrary write.
A RELRO label does not prove a specific relocation writable; inspect the actual
slot's mapping after loader initialization. A later trigger must really use the
modified object. An alternative writable pointer also needs a valid lifetime.

Account for the formatter implementation and fortified wrappers: `%n` may be
rejected under the actual call conditions. Observe rejection rather than assuming
that format control guarantees write access. Positional argument support and
mixed positional/non-positional behavior are implementation-dependent.

For each planned write, record destination, width and desired bytes. Compute
padding modulo that width using the count produced in this same formatting call;
include a literal prefix in the format, not unrelated earlier output. Account for
wraparound, adjacent/overlapping bytes, byte order, output limits and zero padding.
Pwntools helpers need the correct context, argument offset and `numbwritten`;
inspect generated bytes and confirm the resulting memory, rather than treating
helper output as a successful experiment.

## Write-target ladder

Choose the destination in this order, re-deriving from the live process each time:

1. Partial RELRO: a GOT entry of a function the program calls AFTER the
   vulnerable printf — the trigger must exist in the same execution path.
2. Full RELRO: a writable DATA pointer that a later code path dereferences
   (function pointers, dispatch tables, counters the control flow tests).
3. Stack: a saved return address or control variable reachable through the
   leak, when no usable data pointer exists.
4. Heap: a pointer stored in a chunk the format string can address.

For every rung, record WHO reads the modified object and WHEN; a write that
nothing later uses is not a primitive.

## Evidence and stopping condition

Preserve raw format bytes, argument observations, before/after memory, process
identity and a trigger transcript. Distinguish disclosure, bounded write and
executed behavior. Use a no-format or no-write control when it discriminates the
claim. Stop at the requested primitive if further exploitation is unnecessary;
otherwise hand the minimal artifact and predicate to an independent verifier.
